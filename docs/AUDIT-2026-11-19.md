# NVIDIA launch-command audit — 2026-11-19

[Español — full findings and capability matrix](es/AUDITORIA-2026-11-19.md) · [Home](../README.md)

## Status

Audit of the changes from public 2.0.0 (`685984ec104d81599545ad43bcf528f73d304d12`), incorporated into release **2.1.0**. See the [release verification](VERIFICATION.md) for package checks.

## Findings and changes

- The original default K command already included NGX correctly. The reproduced defect was **Reset → select a preset**, which left the optional updater disabled. Preset/model requests now always include their required `PROTON_ENABLE_NGX_UPDATER=1`, including recognized imported requests.
- Initial SR/K selection could silently accompany an unrelated Smooth Motion request. All technologies now start game-controlled; no output until something is selected.
- Selecting only K generates exactly:

```text
PROTON_ENABLE_NGX_UPDATER=1 DXVK_NVAPI_DRS_SETTINGS=NGX_DLSS_SR_OVERRIDE=on,NGX_DLSS_SR_OVERRIDE_RENDER_PRESET_SELECTION=render_preset_k %command%
```

- No RR/FG/DLAA, quality mode, sharpening or other graphics settings are added. Explicitly imported existing parameters are preserved with applicable warnings.
- Update-only is independently available as `PROTON_ENABLE_NGX_UPDATER=1 %command%`. NGX updates do not pin a DLL/marketing version or prove the selected model is running.
- Removed **Ajustes NVIDIA / Linux** and its general controls. Existing Smooth Motion, Vulkan Reflex bridge and NVIDIA sharpening have separate technology panels with the same dark/green design. General FPS/VSync/textures/cache/VRR settings have not been reintroduced under another name. Historical non-UI composition remains for compatibility.
- DLSS indicators remain opt-in diagnostics, with their Wine persistence explained. Presets never turn them on.
- Hardened Smooth Motion conflicts with imported numeric FG settings and Gamescope wrappers; explicitly imported FG-off works. Reflex cannot be enabled while an imported variable disables its layer.

## Capability audit

Smooth Motion, Reflex and sharpening were already implemented, not newly discovered omissions. Documented constraints are retained: RTX 40/50 + NVIDIA present layer and Vulkan for Smooth Motion; integrated Reflex and its optional Vulkan layer for the bridge; R595+ OpenGL/Vulkan for sharpening. Modern winevulkan 1.4.357+ can use a direct Reflex extension route without enabling that bridge.

Newly documented DXVK-NVAPI **NR / NR SL / Streamline override keys** were identified. An accepted DRS enum alone does not establish a useful game/GPU/model support matrix; these are recorded but not exposed as working technologies. No verified Steam/Linux equivalents were found in the reviewed sources for RTX HDR, Dynamic Vibrance, Freestyle, DLDSR, automatic optimization or ShadowPlay. Separate tools/system settings are not presented as those NVIDIA App features.

See the [full matrix](es/AUDITORIA-2026-11-19.md), [primary-source URL/SHA256 manifest](sources/launch-audit-2026-11-19.json), [DXVK-NVAPI driver settings](https://github.com/jp7677/dxvk-nvapi/wiki/Passing-driver-settings), [Reflex requirements](https://github.com/jp7677/dxvk-nvapi#requirements) and NVIDIA's [Smooth Motion](https://download.nvidia.com/XFree86/Linux-x86_64/595.99.02/README/nvpresent.html), [NGX](https://download.nvidia.com/XFree86/Linux-x86_64/595.99.02/README/ngx.html) and [driver-variable](https://download.nvidia.com/XFree86/Linux-x86_64/595.99.02/README/openglenvvariables.html) documentation.

## Verification boundary

**108 unit/UI tests** cover exact commands, feature isolation, dependencies, clipboard outputs, Reset and compatibility/conflicts. Source self-test and visual checks are separate from game runtime verification. Real local GPU: RTX 2060; RTX 5070 UI fixtures are simulated. Screenshots/evidence: `artifacts/audit-2026-11-19/` and `.cache/audit-2026-11-19/`.

The generated K command exactly matches the independently validated Rise of the Tomb Raider command from earlier on 2026-11-19 (official K indicator, DLSS 310.9.16, two starts). No games were relaunched for this revision, no FPS measured, and no physical RTX 40/50 tested. No Steam, DLL or driver changes were needed. Packaging and publication checks for 2.1.0 are documented separately in [VERIFICATION.md](VERIFICATION.md).
